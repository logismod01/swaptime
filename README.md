# СвапТайм 💬

Свой мессенджер на FastAPI + WebSocket: рейл с серверами, каналы с ролями
и участниками, каналы-ленты с постами и подписками, личные чаты, звонки
WebRTC (видео, экран до 4K) и 10 градиентных тем.

Один процесс отдаёт и API, и фронтенд.

## Запуск

```bash
pip install -r requirements.txt
python backend/server.py
```

Открыть <http://localhost:8000>.

Или в Docker (база сохраняется в томе):

```bash
docker build -t swaptime .
docker run -p 8000:8000 -v swaptime-data:/data swaptime
```

База (`data/swaptime.db`) создаётся автоматически. Старая база от предыдущей
версии тоже подхватывается: недостающие колонки добавляются при старте,
старые пароли (SHA-256) продолжают работать и незаметно обновляются
до PBKDF2 при первом входе.

Тесты:

```bash
pip install pytest httpx websockets
python -m pytest tests -q          # API + WebSocket (включая v10)

npm install                        # для UI-тестов (jsdom)
npm run test:ui                    # фронтенд без браузера
```

## Что умеет

- регистрация с капчей и вход по токену;
- друзья: заявки (входящие/исходящие), вкладки «Все / Онлайн / Заявки / Блок»,
  удаление, блокировка, игнор;
- личные чаты в реальном времени (WebSocket), история последних 200 сообщений;
- счётчик непрочитанных с бейджем `1…99+`, синхронизация между вкладками;
- ответы на сообщения с цитатой автора и переходом к оригиналу;
- редактирование и удаление — изменения сразу видны обоим собеседникам;
- онлайн-статус, «печатает…», индикатор отправки и повторная отправка;
- **своя аватарка**: загрузка фото, обрезка в квадрат и сжатие на клиенте;
- **10 кастомных рамок** вокруг аватарки (одна из них анимированная);
- **баннеры профиля**, «о себе», карточка профиля;
- **10 шрифтов** интерфейса с живым предпросмотром;
- **10 градиентных тем**: midnight, ocean, emerald, violet, sunset, cyber,
  coffee, mono, aurora, cherry — применяются сразу и запоминаются;
- **серверы**: свой сервер (название, эмодзи-иконка, описание, цвет),
  текстовые каналы и категории, инвайт-код, роли владелец/админ/участник,
  кик, выход и удаление, непрочитанные по каналам;
- сообщения в каналах сервера: правка и удаление в реальном времени, «печатает…»;
- **закреплённые сообщения** — и в личных чатах, и в каналах серверов:
  панель под шапкой с последним закреплённым, список всех пинов с переходом
  к сообщению и откреплением, синхронизация между собеседниками по WebSocket;
- **каналы-ленты**: создание своего канала (название, описание, цвет,
  публичный/закрытый), лента постов, правка и удаление постов, подписки,
  поиск публичных каналов, непрочитанные;
- **звонки**: аудио и видео P2P (WebRTC), демонстрация экрана до **4K**,
  входящий звонок с принять/отклонить/занято, таймер, статистика
  (битрейт, разрешение, fps, потери, пинг) и настройки: качество (480p…4K),
  fps, битрейт, кодек (VP9/VP8/H.264/AV1/авто), эхоподавление,
  шумоподавление, АКГ, зеркало, 4K-экран — в профиле и прямо в звонке;
- адаптивная вёрстка (на телефоне чат открывается на весь экран);
- **устанавливается как приложение** (PWA): иконка на главном экране,
  отдельное окно без адресной строки, офлайн-заглушка при потере сети;
- **v12**: реакции-эмодзи, поиск по чату и каналу,
  избранное (сохранённые сообщения), черновики, закрепление чатов,
  тихие чаты и уведомления, форматирование текста, «новые сообщения»,
  быстрый переход `Ctrl+K`, статусы «в сети / отошёл / не беспокоить /
  невидимка» с текстом и пересылка сообщений;
- **v13 — десять крупных функций**: фото/файлы/голосовые в сообщениях,
  опросы, категории каналов, реакции на постах каналов,
  глобальный поиск `Ctrl+Shift+F`, папки чатов, мобильная панель вкладок,
  онбординг-тур, статистика сервера и слэш-команды.

## Что нового в v12 (10 функций)

| Функция | Как пользоваться |
|---------|------------------|
| **Реакции** | кнопка 😊 у сообщения (или ＋ рядом с существующими реакциями) → эмодзи. Работает в личке и в каналах сервера, счётчики и «моя реакция» подсвечиваются, всё синхронно по WebSocket |
| **Поиск по чату** | 🔍 в шапке или `Ctrl+F`: подсветка совпадений, счётчик `1/7`, стрелки ↑ ↓ или `Enter` / `Shift+Enter` |
| **Избранное** | 🔖 у сообщения → кнопка 🔖 в рейле. Поиск внутри, переход к оригиналу, «Очистить». Хранится в браузере (`localStorage`) |
| **Черновики** | текст сохраняется на каждый чат и канал автоматически; в списке чатов видно «Черновик: …» |
| **Закрепление чатов** | 📌 на строке чата (появляется при наведении) → закреплённые уходят наверх в группу «Закреплённые» |
| **Тихие чаты** | 🔔/🔕 в шапке чата и канала; список тихих — в настройках → «Уведомления» |
| **Уведомления** | там же: уведомления на рабочем столе (спросит разрешение), звук, превью текста; в заголовке окна показывается число непрочитанных |
| **Форматирование** | кнопка `Aa` у поля ввода или `Ctrl+B` / `Ctrl+I`: `**жирный**`, `*курсив*`, `~~зачёркнутый~~`, `` `код` ``, ```блок кода```, `||спойлер||` (открывается по клику) |
| **«Новые сообщения»** | при открытии чата рисуется разделитель «Новые сообщения» и кнопка ↓ со счётчиком сообщений ниже |
| **Быстрый переход** | `Ctrl+K` (или ⌕ в рейле): поиск по чатам, серверам, каналам и настройкам, ↑ ↓ + `Enter` |
| **Статусы** | настройки → «Мой профиль» → 🟢 в сети / 🌙 отошёл / ⛔ не беспокоить / ⚪ невидимка + текст статуса. Друзья видят его в шапке чата, карточке профиля и списке |
| **Пересылка** | ⇄ у сообщения → выбрать друга; получатель видит «⇄ Переслано от …» |

## Что нового в v13 (10 функций)

| Функция | Как пользоваться |
|---------|------------------|
| **Вложения** | 📎 в поле ввода: фото (сжимается на клиенте, открывается в лайтбоксе), файлы (карточка с именем, размером и скачиванием), ограничение ~1,8 МБ. Работает в личке и в каналах серверов |

| **Опросы** | 📊 или команда `/poll`: вопрос + 2–6 вариантов. Голос один на человека, меняется повторным кликом, результаты обновляются у всех в реальном времени (`poll_update` по WebSocket) |
| **Категории каналов** | при создании канала укажи категорию (или ✎ у канала), в сайдбаре появятся сворачиваемые группы — состояние запоминается |
| **Реакции на постах** | у каждого поста канала-ленты теперь есть реакции: 😊 → эмодзи, счётчики общие для владельца и подписчиков |
| **Глобальный поиск** | `Ctrl+Shift+F`: ищет сразу по людям, личным сообщениям, каналам серверов и постам каналов. Клик по результату открывает нужный чат и подсвечивает сообщение |
| **Папки чатов** | полоска над списком чатов: Все / Непрочитанные / Личные / Серверы / Каналы, плюс «＋» — своя папка с фильтром |
| **Мобильная панель** | на телефоне внизу появляются вкладки «Чаты / Каналы / Серверы / Друзья / Ещё» с бейджами непрочитанного, композер поднимается над панелью |
| **Онбординг-тур** | при первом входе — четыре подсказки с подсветкой элементов (рейл, список чатов, поле ввода, поиск). «Пропустить» больше не показывает тур |
| **Статистика сервера** | 📊 в шапке каналов сервера: сообщения за 7/30 дней, график по дням, топ участников и распределение по каналам |
| **Слэш-команды** | начни с `/` — появятся подсказки (↑ ↓, `Tab`): `/spoiler`, `/me`, `/shrug`, `/tableflip`, `/unflip`, `/roll 1-100`, `/poll` |

### Исправление «сломанной» раскладки

Если чат-колонка обрывалась, сообщения уезжали под композер, а левая панель
тянулась пустой полосой — это был старый CSS из кеша либо масштаб страницы.
Теперь каркас защищён на трёх уровнях:

1. в `index.html` встроен минимальный критический CSS — даже если `style.css`
   не загрузился, приложение остаётся в рамках окна;
2. `frontend/layout-guard.js` жёстко задаёт геометрию каркаса (inline `!important`),
   сверяет высоту с окном раз в секунду и подгоняет её при зуме/повороте экрана;
3. если таблица стилей не загрузилась, стражовка один раз перезапрашивает
   `style.css` с новым адресом и чистит старые кеши service worker'а.

## Почему правки CSS могут «не доезжать»

Если после обновления сервера интерфейс выглядит сломанным (например, лента
чата не на всю высоту), почти всегда виноват кеш браузера или старый
service worker. В v12 это вылечено на трёх уровнях:

1. ссылки на статику получают хеш содержимого — `/static/style.css?v=<md5>`;
   хеш считается на старте сервера, поэтому любой изменённый файл получает
   новый адрес;
2. `/static/*` отдаётся с `Cache-Control: no-cache` — браузер всегда
   перепроверяет файл;
3. service worker для статики работает по схеме «сначала сеть», новая версия
   активируется сразу и один раз перезагружает страницу.

Если всё же видишь старое: `Ctrl+Shift+R` (жёсткая перезагрузка) или
DevTools → Application → Service Workers → Unregister.

## Как открыть сайт и сделать из него приложение

Коротко: **GitHub Pages не подойдёт** — там хостится только статика, а СвапТайму
нужен Python-процесс (API + WebSocket). Поэтому GitHub хранит код и гоняет тесты,
а «живой» сайт поднимается на любом хостинге, который умеет Python и WebSocket.
Дальше сайт ставится как приложение (PWA) — иконка на телефоне/десктопе,
отдельное окно без адресной строки.

### 1. Что можно проверить прямо на GitHub

| Где | Что смотреть |
|-----|--------------|
| вкладка **Actions** | каждый push прогоняет `pytest tests` и `npm run test:ui` — зелёные галочки = код рабочий |
| вкладка **Code** | исходники: `backend/server.py` (API), `frontend/*` (интерфейс), `tests/*` |
| **README** | инструкции, список API и переменных окружения |
| **Releases** | (по желанию) теги версий: `git tag v11 && git push --tags` |

Тесты запускаются автоматически из `.github/workflows/ci.yml` — ничего настраивать не нужно.

### 2. Поднять сайт: Render.com (проще всего, есть бесплатный план)

1. На GitHub: **Fork** репозитория (или используй свой).
2. Зайди на <https://render.com> → **New +** → **Blueprint**.
3. Выбери свой репозиторий — Render сам прочитает `render.yaml`.
4. Жми **Apply**. Через 2–3 минуты получишь адрес вида
   `https://swaptime-xxxx.onrender.com` — это и есть твой сайт.

Нюансы бесплатного плана: сервис «засыпает» после ~15 минут без запросов
(первый заход после сна — 30–60 секунд), а диск недоступен, поэтому база
обнулится при перезапуске. Для постоянного хранения переключи план на `starter`
(в `render.yaml` уже прописан диск `/var/data`).

### 3. Поднять сайт: свой сервер / VPS

```bash
git clone https://github.com/<твой-ник>/swaptime.git
cd swaptime
docker build -t swaptime .
docker run -d --name swaptime --restart unless-stopped   -p 127.0.0.1:8000:8000 -v /srv/swaptime-data:/data swaptime
```

Дальше нужен **HTTPS-домен** (без него не работают камера, микрофон и
установка приложения). Проще всего Caddy — он сам выпускает сертификат:

```
# /etc/caddy/Caddyfile
chat.example.com {
    reverse_proxy 127.0.0.1:8000
}
```

Caddy проксирует и WebSocket (`/ws`) автоматически. С nginx понадобится
`proxy_set_header Upgrade $http_upgrade; proxy_set_header Connection "upgrade";`
для `/ws` и `proxy_read_timeout 3600s;`.

### 4. Показать друзьям без сервера

```bash
python backend/server.py            # локально на 8000
cloudflared tunnel --url http://localhost:8000     # или: ngrok http 8000
```

Туннель выдаёт HTTPS-адрес — по нему работают и звонки, и установка приложения.
Ссылка живёт, пока запущен туннель.

### 5. Установить как приложение (PWA)

В проекте уже есть всё нужное: `manifest.webmanifest`, service worker `/sw.js`
(кеш интерфейса + офлайн-страница), иконки, `display: standalone`
и кнопка **⬇ Установить приложение** в панели профиля.

| Платформа | Как установить |
|-----------|----------------|
| **Android / Chrome** | открыть сайт → меню ⋮ → «Установить приложение» (или кнопка ⬇ в интерфейсе) |
| **iPhone / iPad (Safari)** | «Поделиться» → «На экран Домой» |
| **Windows / macOS / Linux** | иконка «установить» в адресной строке Chrome/Edge, либо меню → «Установить СвапТайм» |
| **Firefox** | отдельного ярлыка нет — работает как обычная вкладка |

После установки приложение открывается в своём окне, без адресной строки,
иконка лежит на главном экране/рабочем столе. Обновления приезжают сами:
service worker тянет новый интерфейс из сети, при появлении новой версии
показывается подсказка «перезапусти приложение».

**Требования для установки:** HTTPS (или `localhost`) и открытая главная
страница. В iframe-превью установка недоступна — открывай ссылку отдельной
вкладкой.

### 6. Переменные окружения

| Переменная | По умолчанию | Зачем |
|------------|--------------|-------|
| `PORT` | `8000` | порт сервера (хостинги задают сами) |
| `SWAPTIME_DB` | `data/swaptime.db` | путь к базе SQLite (на хостинге — на диск) |
| `SWAPTIME_TURN_URL` | — | TURN для звонков, можно несколько через запятую |
| `SWAPTIME_TURN_USER` / `SWAPTIME_TURN_PASS` | — | логин/пароль TURN |

TURN нужен, когда оба собеседника за строгим NAT и P2P не пробивается:
бесплатный вариант — <https://www.metered.ca/tools/openrelay/> или свой coturn.
Сервер отдаёт настройки через `GET /api/ice`, клиент берёт их при звонке.

### 7. Чеклист «всё ли работает» после публикации

1. `https://твой-адрес/` открывается, есть экран входа.
2. Регистрация → попадаешь в интерфейс, слева рейл, снизу шестерёнка.
3. ⚙ → «Внешний вид» → темы переключаются.
4. «＋» в рейле серверов → создаётся сервер с каналами `#общий` и `#флудилка`.
5. 📣 → «Создать канал» → пост появляется в ленте.
6. Два аккаунта (второй — в инкогнито) → друзья → 📞 звонок: слышно друг друга,
   🖥 шаринг экрана, ⚙ качество/битрейт.
7. На телефоне: «Установить приложение» → иконка СвапТайм на главном экране.

## API (кратко)

Токен принимается тремя способами (в порядке приоритета):
`Authorization: Bearer <token>`, `?token=<token>` и HttpOnly-cookie,
которую сервер ставит при входе. Cookie и query — запасные пути на случай,
если прокси срезает заголовок `Authorization`.

| Метод | Адрес | Что делает |
|-------|-------|------------|
| POST | `/api/register`, `/api/login`, `/api/logout` | аккаунт и сессия |
| GET | `/api/me` | текущий пользователь + шрифты, рамки, баннеры, темы |
| POST | `/api/reactions` | реакция; `scope`: `dm` / `channel` / `tg_post` |
| POST | `/api/polls/vote` | голос в опросе: `{scope, message_id, option}` |
| GET | `/api/search/global?q=` | глобальный поиск: люди, ЛС, каналы серверов, посты |
| GET | `/api/servers/{id}/stats?days=7` | статистика сервера: дни, участники, каналы |
| POST | `/api/update_profile` | имя, цвет, шрифт, рамка, баннер, био |
| POST | `/api/avatar` | загрузить/удалить аватарку (data URL, ≤ 300 КБ) |
| GET | `/api/avatar/{username}` | файл аватарки (кеш на год, ETag) |
| GET | `/api/profile/{username}` | карточка профиля |

События WebSocket: `message`, `message_updated`, `read`, `read_sync`,
`typing`, `presence`, `friend_request`, `friend_changed`,
`profile_updated`, `server_message`, `server_message_updated`,
`server_typing`, `server_channels_changed`, `server_members_changed`,
`server_member_joined`, `server_member_left`, `server_updated`, `server_left`,
`tg_post`, `tg_post_updated`, `tg_channel_deleted`,
`call_incoming`, `call_accept`, `call_reject`, `call_end`, `call_busy`,
`call_signal`, `call_error`, `pin_changed`, `server_pin_changed`, `reaction`,
`error`, `pong`.

Реакции: WS `{"type":"reaction","scope":"dm","id":...,"emoji":"👍"}` (для канала
`"scope":"channel"`), сервер отвечает событием `reaction` со списком
`{emoji, count, users}`.

Пересылка: к обычному `message` добавляются `fwd_from` и `fwd_name` — сервер
проверяет, что автор существует, и сохраняет подпись «Переслано от».

Закрепление: WS `{"type":"pin_msg","id":...,"pinned":true}` для личного чата и
`{"type":"server_pin_msg","id":...,"pinned":true}` для канала сервера; сервер
отвечает событием с полным сообщением всем, кому оно видно. Удаление сообщения
автоматически снимает закрепление.

## Аватарки и рамки

Фото обрабатывается **на клиенте**: центр-кроп в квадрат, ресайз до 256×256
и сжатие (JPEG/PNG), поэтому на сервер уходит ~20–60 КБ вместо мегабайтов.
Хранится как data URL в поле `users.avatar`, отдаётся через `/api/avatar/{ник}`
с версией в URL (`?v=...`), чтобы браузер не показывал старую картинку.

Рамки: `none, crimson, gold, neon, aurora, fire, ice, galaxy, rainbow, mono`.
Баннеры: `crimson, sunset, ocean, forest, galaxy, night, mono`.

## Серверы и каналы (v10)

При создании сервера сразу появляются каналы `общий` и `флудилка`, а владелец
получает инвайт-код (`POST /api/servers/join {code}`). Владелец может менять
роли (`admin`/`member`), исключать участников (`.../members/{ник}/kick`),
пересоздать код (`.../rotate_invite`) и удалить сервер; админы — создавать
каналы и удалять сообщения; участники — писать.

Каналы-ленты — отдельная сущность: у канала есть владелец, описание, цвет и
флаг `is_public`. Публиковать может только владелец, остальные подписываются
и читают. Публичные каналы ищутся через `GET /api/tg/discover?q=`.

## Звонки

Сигналинг идёт по тому же WebSocket (`{"type":"call", "action": ...}`),
медиа — напрямую между браузерами (STUN-серверы Google/Twilio).
Звонить можно друзьям и участникам общих серверов. Качество задаётся
в настройках: пресеты 480p/720p/1080p/1440p/4K, fps 15–60, битрейт
1–20 Мбит/с, предпочтительный кодек; всё это применяется на ходу через
`RTCRtpSender.setParameters`. Демонстрация экрана запрашивается
в 3840×2160 при включённом 4K и переключается на лету (`replaceTrack`).
Панель статистики показывает битрейт, разрешение, fps, потери пакетов и пинг.
